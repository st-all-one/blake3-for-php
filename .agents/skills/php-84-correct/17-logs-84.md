# Logs e Tratamento de Erros no PHP 8.4

Este documento complementa `06-logs.md` com as mudanças de logging/erros
introduzidas até o PHP 8.4. Todo o conteúdo é aplicável em 8.4.

## 1. Níveis de erro e o valor de `E_ALL` no 8.4

O PHP agrupa erros em níveis. O valor numérico de `E_ALL` **mudou para 30719**
no PHP 8.4 (reflete a inclusão/remanejamento de categorias ao longo das
versões).

```php
echo E_ALL; // 30719 no PHP 8.4
```

Níveis principais (constantes):

| Constante | Significado (8.4) |
| --- | --- |
| `E_ERROR` | erros fatais em runtime |
| `E_WARNING` | avisos em runtime |
| `E_PARSE` | erros de parsing |
| `E_NOTICE` | notas em runtime |
| `E_DEPRECATED` | uso de recursos obsoletos do próprio PHP |
| `E_USER_DEPRECATED` | obsoleto disparado por código do usuário (via `#[\Deprecated]`) |
| `E_USER_ERROR` | **depreciado** ao usar com `trigger_error()` (ver seção 4) |
| `E_USER_WARNING` | aviso do usuário |
| `E_USER_NOTICE` | nota do usuário |
| `E_RECOVERABLE_ERROR` | erro recuperável |
| `E_STRICT` | **depreciado / não usado** (ver seção 5) |
| `E_ALL` | todos (valor 30719 no 8.4) |

## 2. `error_reporting` padrão e logging

Desde o PHP 8.0, `error_reporting` é `E_ALL` por padrão. Recomendação de
produção (ver `16-configuracao-84.md`):

```ini
error_reporting = E_ALL
log_errors = On
error_log = /var/log/php/php-error.log
display_errors = Off
display_startup_errors = Off
```

Em runtime:

```php
error_reporting(E_ALL);
ini_set('log_errors', '1');
```

## 3. `error_log_mode` (PHP 8.2)

Define a máscara de permissão (mode) aplicada ao arquivo de `error_log` quando
o PHP o cria. Útil para evitar permissões largas indevidas.

```ini
error_log = /var/log/php/php-error.log
error_log_mode = 0640
```

```php
ini_set('error_log_mode', '0640');
```

## 4. `E_USER_ERROR` via `trigger_error()` — DEPRECIADO no 8.4

Chamar `trigger_error()` com `E_USER_ERROR` está **depreciado** no PHP 8.4.
Deve-se substituir por lançamento de exceção ou `exit()`.

```php
// ❌ Depreciado no 8.4
trigger_error('Falha fatal', E_USER_ERROR);

// ✅ Recomendado
throw new RuntimeException('Falha fatal');
// ou, se for encerramento: exit(1);
```

- `trigger_error()` e `user_error()` ainda existem (retornam `true` desde o
  8.4), mas `E_USER_ERROR` como nível está obsoleto.
- `E_USER_WARNING` e `E_USER_NOTICE` continuam válidos.

## 5. `E_STRICT` — DEPRECIADO / NÃO USADO no 8.4

A constante `E_STRICT` foi removida como nível de erro efetivo e sua constante
está **depreciada** no 8.4. Não a use em `error_reporting` (não produz efeito
prático). Use `E_ALL` que já cobre o necessário.

```php
// Não faça mais isso:
error_reporting(E_ALL | E_STRICT); // E_STRICT depreciado

// Faça:
error_reporting(E_ALL);
```

## 6. Atributo `#[\Deprecated]` (PHP 8.4) para `E_USER_DEPRECATED`

Substitui a documentação de obsolecência por metadado oficial. Quando o
elemento marcado é usado, emite `E_USER_DEPRECATED` (não `E_DEPRECATED`),
permitindo captura via handler.

```php
class Api
{
    #[\Deprecated('Use novaMetodo()', since: '3.0')]
    public function metodoAntigo(): void {}
}

set_error_handler(function ($errno, $errstr) {
    if ($errno === E_USER_DEPRECATED) {
        error_log("Depreciação: $errstr");
        return true; // não propaga
    }
    return false;
});

$api = new Api();
$api->metodoAntigo(); // emite E_USER_DEPRECATED
```

- Mensagem e `since` são opcionais; melhoram a mensagem de log.
- Aplicável a funções, métodos e constantes de classe.

## 7. Logging estruturado e syslog

- `error_log($msg)` envia para o destino configurado (`error_log` ini ou syslog).
- `syslog($priority, $msg)` / `openlog()` / `closelog()` para syslog.
- Diretivas `syslog.filter` (8.1), `syslog.facility` e `syslog.ident` (7.3+)
  ajudam a filtrar/rotular mensagens.

```ini
syslog.ident = meuapp
syslog.facility = LOG_LOCAL0
```

- Prefira bibliotecas de logging (PSR-3) para aplicações maiores; use
  `error_log()` para alertas críticos do SAPI.

## 8. Exceções e erros (modelo 8.4)

Desde o PHP 7, erros e exceções implementam `Throwable`. Em 8.4 esse modelo
permanece: `try/catch (Throwable $e)` captura tanto `Exception` quanto `Error`
(incluindo `TypeError`, `ValueError`, `AssertionError`).

```php
try {
    operacao();
} catch (ValueError $e) {
    error_log('Valor inválido: ' . $e->getMessage());
} catch (Throwable $e) {
    error_log($e::class . ': ' . $e->getMessage());
}
```

## 9. Resumo das mudanças de 8.4 em logs/erros

| Item | Status em 8.4 |
| --- | --- |
| `E_ALL` | valor **30719** |
| `E_USER_ERROR` via `trigger_error()` | **depreciado** (use exceção/`exit`) |
| `E_STRICT` | **depreciado / sem efeito** |
| `#[\Deprecated]` | emite `E_USER_DEPRECATED` |
| `error_log_mode` | disponível (desde 8.2) |
| `error_reporting` default | `E_ALL` (desde 8.0) |

Todos os exemplos acima são executáveis/em aplicáveis em PHP 8.4.
